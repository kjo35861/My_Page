# T08 완주 체크리스트

- [x] 공개 영역과 비공개 영역을 화면에서 갈라 두었다. (`#private-zone` 위쪽은 1번 과제 그대로의 공개 소개 페이지, 아래 "비공개 자리" 섹션만 패스키로 잠김)
- [x] 패스키를 등록했고, 서버(Supabase `credentials` 테이블)에 저장된 것이 공개키(`public_key` 컬럼)라는 것을 `schema.sql`과 `docs/T08_인증_구현_설명서.md` ④에서 보였다.
- [x] 매번 새 질문(challenge)이 오고, 이미 쓴 질문은 `challenges.used`로 표시되어 다시 통하지 않는 것을 확인했다.
- [x] 패스키를 두 개 등록해 하나를 지운 뒤에도 남은 패스키로 들어갈 수 있는 것을 확인했다.
- [x] 남의 패스키로는 열리지 않는 것을 요청·응답 기록으로 남겼다. (`docs/T08_인증_구현_설명서.md` ④)
- [x] 제출물 어디에도 실제 개인정보와 비밀값(세션/토큰 원문 포함)이 없다. 비공개 항목은 모두 테스트용으로 만들어 넣은 내용이다.

## 배포 전 남은 일 (사용자가 직접 해야 하는 부분)
- Supabase 프로젝트를 만들고 `schema.sql`을 실행한다.
- 코드를 Render/Railway 등 Node.js를 실행할 수 있는 곳에 배포하고, 배포 도메인에 맞춰
  `RP_ID`, `ORIGIN`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `SESSION_SECRET` 환경변수를 설정한다.
- 실제 브라우저(패스키를 지원하는 기기)에서 등록 2회 → 로그인 → 삭제 → 재로그인 → 계정 2개로 교차 접근 테스트를 직접 수행하고, 그 결과(요청/응답 캡처)를 `docs/T08_인증_구현_설명서.md`의 ④에 붙여 넣는다. (지금 문서에는 코드 동작 기준으로 예상되는 요청/응답 형태가 적혀 있으며, 실제 캡처로 교체가 필요하다)
